> **Project Documentation Update (Required After Every Completed Task)**
>
> After completing any task, update the project tracking/documentation file before finishing.
>
> Ensure the following sections are reviewed and updated:
>
> * **Project Details:** Add or revise any relevant project information.
> * **Features Implemented:** Document all newly completed features or enhancements.
> * **Bugs Fixed:** Record each bug that was resolved, including a brief description.
> * **Known Issues:** Add newly discovered issues or update the status of existing ones.
> * **Task Status:** Mark the task with its current status (e.g., Completed, In Progress, Blocked, Deferred).
> * **Completion Date:** Record the task's completion date using the project's standard date format.
>
> **Requirements:**
>
> * Keep entries accurate, concise, and consistent with the existing document structure.
> * Update only the relevant sections; do not remove or overwrite unrelated information.
> * If a section does not exist, create it using the established documentation format.
> * Ensure the documentation reflects the latest project state before considering the task complete.
> * Treat documentation updates as a mandatory part of the task completion workflow, not an optional follow-up.
